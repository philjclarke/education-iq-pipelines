# Education IQ AI Pipelines: admin and reporting prototype

An interactive prototype of the Education IQ pipeline builder. A data scientist can define inputs, build generation, validation and check steps through a guided prompt builder, route results, test a draft live and publish a version. The team can then follow every request from submission to an Athena delivery.

Everything runs in the browser on sample data. **Model calls, costs and Athena deliveries are simulated.** All schools, excerpts and figures are fictional.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # engine tests (routing, retries, limits, seed history)
npm run build      # production build in dist/
```

Edits, test cases and requests persist in the browser (IndexedDB). To restore the seeded state, use **Prototype settings → Reset demo data**.

## Demo script (the brief's acceptance journeys)

1. **Build or edit the Ofsted pipeline.** Pipelines → Ofsted theme summary → *Edit draft V2*. Inputs shows fixed and dynamic inputs with a preview by organisation. *Steps & prompts* has the guided questions, a live prompt preview, the output schema and the routing rules. The validator uses a different provider from the generator.
2. **Run a sample and the suite.** Open the *Test* tab and choose *Run test suite*. The traces update live. “No unsupported claims reach the validator” fails: open its trace, choose *Open evidence instructions (Q6)*, click *Use this example* (it adds a rule about awards and accreditations), and rerun the case. The comparison shows the prompt diff and the changed route.
   Then, in *Validate claims against evidence → Routing*, change the confidence threshold from 0.8 to 0.7 and rerun “Low-confidence pass goes to second review”. The same seeded response now completes without a second review.
3. **Publish a new version.** Open *Review & publish*, enter an approver and confirm. The three queued requests stay on V1. *Submit request* creates a new request on V2.
4. **Missing input.** Requests → filter by *Missing input* (Riverside Studio School). It shows the missing `Ofsted` type reference, 0 model calls and £0.00.
5. **Retry from a step.** Open a completed Ashcombe Upper School request. The validator timed out, and attempt 2 restarted from validation, reusing the outputs of the earlier steps (marked *Reused from attempt 1*).
6. **Review and delivery.** In Manual review, open a Fenwick Park case, choose *Edit and approve*, remove the unsupported sentence and approve. The original candidate is kept. Then filter requests by *Delivery failed* and choose *Retry delivery*. The AI attempt history doesn’t change.

*Run worker* processes the queue, including the scheduled retry. *Prototype settings* can simulate an Athena outage.

## How it’s built

| Folder | What it holds |
|---|---|
| `src/domain` | Types that mirror the SQL Server data model (§1 of the brief) |
| `src/engine` | Pure logic: input capture, prompt assembly, schema validation, deterministic checks, routing, the runner (attempts, reuse, limits), config validation, and the simulated provider |
| `src/services` | Operations that mirror the stored-procedure contracts: submit, claim, process, review, deliver, publish and test |
| `src/data` | A `DbAccess` interface with a browser store implementation. Replacing this with a production API is the intended swap point |
| `src/seed` | Fictional sample content, the Ofsted and News pipelines, test cases and a history plan |
| `src/pages`, `src/ui` | Screens and components |

The seeded history is generated by running the real engine over a plan of submissions on a virtual clock, so every seeded trace comes from the same code that runs live.

**The simulated provider.** Generation steps follow scripted scenarios per organisation, so tests are repeatable. Validators read the candidate they are actually given, so changes to the prompt change the verdict. Routing is always evaluated live from the configured rules.

### Not yet modelled

- The preparation route for evidence that exceeds a model’s input budget is flagged, not executed.
- Authentication: use the *Acting as* switcher.
